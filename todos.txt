--- homeapp file-structure redesign (multi-phase) ---

phase 1 (DONE, 2026-08-17): inserted documents/media/appdata as three sibling branches inside each workspace. core/workspaces.py::path() now returns <root>/documents instead of <root> itself; new root() gives the true workspace root. ark keeps working exactly as it did before - same .txt extension, same note/todo/evnt dirs, vendored binary completely untouched - just nested one level deeper on disk. real server data migrates automatically and idempotently on server startup (core/storage.py::_migrate_documents_layout(), same "check current shape, fix if needed, run every boot" convention as core/db.py's own schema fixups) - no manual script to run. media/ and appdata/ are not eagerly created (nothing writes to them yet) and are not git-tracked - see the two "open decision" sync items below, which are follow-ups, not blockers. verified: migration idempotency + empty-workspace handling, full Flask-test-client flow (new workspace creation, save, lock, documents scan, enable_git puts .git inside documents/ correctly), and a real dev-server run against a seeded old-layout directory - zero errors, migration fired correctly on real startup.

phase 2: SCRAPPED (2026-08-18). Considered redesigning ark to drop the note/todo/evnt/yyyy/mm structure in favour of one flat, .arkrc-configurable output folder with date-first batch filenames. Rejected after realising two things: (1) most notes are multiline, and multiline notes each get their own file rather than being batched (only oneline records get consolidated) - so "flat" would mean thousands of individual files in one folder over time, not a small number of batches, which is exactly the "ever-growing flat folder" problem the redesign was trying to avoid; (2) type-as-directory (note/todo/evnt) and date-as-directory (yyyy/mm) are separate axes that got conflated during the design discussion - only the type axis was actually in tension with ark's "data is the index" philosophy, and a full flat layout traded that problem for a worse one (bulk human/terminal browsability) without a real win.

  decision: ark's internal file structure is staying exactly as it is, permanently. note/todo/evnt/yyyy/mm directories, .txt extension, filenames are ark-generated (yyyymmddThhmmss.txt) or the title metadata property if set - none of this changes. this is a closed design question now, not an open one - don't relitigate scan-performance or flat-folder ideas for ark's own directory layout without a genuinely new argument. "the data is the index" (no cache/index, full live scan every query) is still the permanent philosophy for ark, just realised via the existing note/todo/evnt/yyyy/mm tree rather than a flat one.

  vendored ark (apps/ark/vendor, submodule of benjaminingreens/ark.git) and the real upstream repo at /home/benjamin/ark need no changes as a result of this decision - phase 2 never got past planning, no code was touched.

phase 3: rename Documents -> Files. generic display only (no ark-specific tag/record parsing baked in - that stays inside the dedicated ark app, which remains the place for an ark-focused view). browses documents/ + media/ branches. basic unix-like commands only (browse/filter/search, maybe rename/move/delete) - no shell-style invocation of other apps' commands from inside files; that stays via HOME's normal app-switcher, to avoid files needing per-app awareness.

open decision: sync mechanism for media/ - git is a poor fit for binary media (no meaningful diff/merge, full-history bloat without LFS). leaning toward a simpler rsync/syncthing-style whole-file mirror (no history) instead of git, but not decided or designed yet.

open decision: sync approach for appdata/ - likely needs a per-app answer rather than one universal mechanism. e.g. chat is probably server-authoritative (no real local-first copy to reconcile) rather than needing the same offline-sync treatment as documents/media. not decided.

open question: chat currently stores data at HOME_DATA_DIR/chat/<group_id>.txt - scoped to group, not workspace. doesn't cleanly fit "one appdata per workspace" without deciding what happens when a group has multiple workspaces. not resolved, chat not moved yet.
